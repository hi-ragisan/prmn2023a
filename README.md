# ばんえい競馬 予測AI (banei_ai)

帯広ばんえい競馬の単勝を対象に、

1. **馬の良し悪し**（レーティング・近走・水分/負担重量補正タイム・馬場水分適性・負担重量の増減）
2. **騎手の良し悪し**（経験ベイズで縮小した勝率、馬の強さを統制した固有の腕）
3. **オッズの歪み**（市場が付けた確率と実際の勝率のズレ）

の3つを組み合わせ、「**市場（オッズ）が間違えている馬**」を探すためのツール一式です。

> ⚠️ 馬券の購入は自己責任で。バックテストの回収率は将来の利益を保証しません。

---

## 考え方

### なぜ「オッズの歪み」なのか
単勝オッズは大勢の予想の集約で、それ自体がかなり正確な勝率予測です。
「強い馬を当てる」だけでは、強い馬は人気になってオッズが下がるので儲かりません。
儲かる可能性があるのは **AIの勝率 × オッズ > 1（期待値プラス）** の馬、つまり
**市場がその馬の勝率を低く見積もりすぎている（歪んでいる）** 場合だけです。

### 二段階モデル（Benter 方式）

```
                ┌──────────────────────────────┐
 過去成績 ───▶ │ 特徴量 (時点整合: 前日までの結果だけ) │
                └──────────────┬───────────────┘
                               ▼
           Stage1: LightGBM ランキング学習 rank_xendcg (オッズは使わない)
                  → 馬・騎手・負担重量・水分から「強さスコア s1」
                               ▼
           Stage2: 条件付きロジット
                  u = a·s1 + b·log(市場確率) + c·騎手人気度 + ...
                  → AI勝率 p_model (レース内で合計 1)
                               ▼
     歪み = p_model / 市場確率 − 1      期待値 = p_model × 単勝オッズ
```

- Stage1 にオッズを入れないのは、モデルが市場の真似をするだけになるのを防ぐため。
- Stage2 で「市場の情報」と「モデルの情報」を最適な重みで混ぜます。
  Stage2 の係数を見ると、市場がどこで間違えているかが分かります
  （例: `j_popularity` の係数が負 → 人気騎手は市場に過大評価されている）。
- Stage2 は Stage1 の**サンプル外**スコアだけで学習します（過信を防ぐ）。

### 特徴量（`banei_ai/features.py`）

| 区分 | 主な特徴量 | 意味 |
|---|---|---|
| 馬 | `h_rating` | 多頭数 Elo レーティング（誰に勝ったか） |
| 馬 | `h_spd_*` | **水分・負担重量補正タイム**（基準タイム − 実タイム, 秒）。基準は過去データだけで逐次推定 |
| 馬 | `h_ewm_pct`, `h_last1_pct` … | 近走の着順パーセンタイル（時間減衰平均） |
| 馬 | `h_avg3_gap`, `h_best5_gap` | 勝ち馬とのタイム差 |
| 馬 | `h_moist_apt` | 今回と同じ水分帯での成績 − 全体平均（縮小推定） |
| 馬 | `cw_rel`, `h_cw_change`, `cw_ratio` | 負担重量のレース内相対値・前走比・馬体重比 |
| 馬 | `horse_weight_diff` | 馬体重の増減 |
| 騎手 | `j_win_ae`, `j_top3_ae` | 実勝利 ÷ 期待勝利(1/頭数)。経験ベイズで縮小、時間減衰あり |
| 騎手 | `j_mkt_ae` | 実勝利 ÷ **市場の**期待勝利(Σ市場確率)。>1 なら市場が過小評価 |
| 騎手 | `j_popularity` | 騎手の人気度（平均市場シェア×頭数） |
| 騎手 | `j_moist_rel` | 騎手×馬場水分の相性（今回の水分帯での成績 ÷ 騎手全体の成績） |
| 調教師 | `t_win_ae` | 同上（調教師） |
| コンビ | `jh_win_ae` | 騎手×馬コンビの実績 |
| 相対 | `r_*_diff`, `r_*_rank` | 上記のレース内での平均との差・順位 |

すべて「その日より前の結果」だけから作ります（`tests/test_core.py::test_no_future_leakage` で検査）。

## 使い方

### 1. 過去データを集める

```bash
# netkeiba (結果表に単勝オッズ・人気・タイム・馬体重がまとまっている)
python -m banei_ai.cli scrape --start 2026-10-01 --end 2026-10-31 --source netkeiba --check
# 問題なければ期間を広げる (3年分 ≒ 450開催日 × 11R、2秒間隔で数時間)
python -m banei_ai.cli scrape --start 2023-04-01 --end 2026-10-31 --source netkeiba
```

> **過去データは netkeiba から取ってください。** 公式 keiba.go.jp は過去レースの単勝オッズが空欄で
> （オッズのページも約半年分しか残らない）、オッズの歪みを学習できません。公式サイトは当日のオッズ取得に使います。

- 取得した HTML は `data/raw/` にキャッシュされ、再実行時は再取得しません。
- **各サイトの利用規約・robots.txt を確認し、私的利用の範囲で低頻度に**使ってください（既定 2 秒間隔）。
- ⚠️ 開発環境から実サイトにアクセスできなかったため、**ばんえいの実ページそのものでは未検証**です。
  代わりに、公開されている keiba.go.jp の実ページの保存物（他場。全場共通のテンプレート）と、
  他の人が公開している実働パーサーで構造を確認し、見つかった不具合（公式成績表が常に 0 レースになる、
  出馬表が読めない、複勝オッズの幅の誤読、netkeiba の文字コード UTF-8 化、馬場水分「水分量:1.6」の % なし表記 など）を修正済みです。
  詳細と残る未確認点は `docs/scraper_verification.md`。
- まず1日分を取得し、診断ツールで中身を確認してください（どの表を選んだか・見出しの対応・水分やIDが取れているか）:
  ```bash
  python -m banei_ai.scrape.diagnose "https://nar.netkeiba.com/race/result.html?race_id=202665110101"
  python -m banei_ai.cli scrape --start 2026-11-01 --end 2026-11-01 --check
  ```
- ばんえいの馬場水分は平地と用語が逆です（水分が多い＝「軽馬場」で時計が速い、乾燥＝「重馬場」）。
- 場コードは `banei_ai/config.py` にあります（netkeiba の帯広ばんえい = `65`、keiba.go.jp の `k_babaCode` = `3`）。
  1日分取得して 0 レースになる場合は、ブラウザで該当ページの URL を確認してここを直してください。

日々の運用では、データの最終日から昨日までを追加取得できます:

```bash
python -m banei_ai.cli update
```

手持ちの CSV がある場合（日本語見出し可）:

```bash
python -m banei_ai.cli import-csv --in mydata.csv
```

必要な列（`banei_ai/schema.py` 参照）: `date, race_no, post(馬番), horse_name(馬名), jockey_name(騎手), finish(着順)`
＋ あると良い列: `odds_win(単勝), carried_weight(負担重量), moisture(馬場水分), time(タイム), horse_weight(馬体重), race_class`。

### 2. 検証する（ウォークフォワード・完全サンプル外）

```bash
python -m banei_ai.cli backtest            # → data/reports/backtest.md
```

2か月ごとに「それ以前のデータだけで学習 → 次の2か月を予測」を繰り返し、
- 対数損失（市場そのまま／較正後／ファンダメンタル／合成モデル）
- 期待値しきい値ごとの回収率・的中率・最大ドローダウン・1/4ケリーの資金推移
- 回収率の 90% 信頼区間（レース単位ブートストラップ）、四半期ごとの安定性、確率の較正

- **前半で選んだしきい値を後半にそのまま適用した成績**（しきい値選びの楽観バイアスを除いた、最も正直な目安）

- **自分の購入によるオッズ低下と締切前オッズのズレを入れた回収率**（単勝売上の規模 × 1点の金額 × オッズのズレ）と、
  「どこまで買うと優位が消えるか」の金額（`--pool-yen`（既定 250万円）, `--odds-noise`, 詳細は `docs/backtest_realism.md`）

を出します。

**本番投入の判断基準（重要）**: 回収率の数字だけで判断しないでください。シミュレーションの空振りテスト
（`docs/robustness.md`）で、**全馬の真の期待値が 0.80 の市場でも、85 点の購入で回収率 163% が出る**ことが確認されています。
また AI が「期待値 1.18」と判断した馬の真の期待値は 0.80 でした（AI の見積もりが偶然高く出た馬ばかり選ぶため）。
判断は次の順で行います:
1. **合成モデルの対数損失が「較正後の市場」より良い**（`vs_market` が `市場 (較正後)` の行より大きい）
2. それが**四半期ごと・前後半のどちらでも一貫して**いる
3. その上で、後半の回収率の信頼区間を参考にする

### 3. 騎手・馬・歪みのレポート

```bash
python -m banei_ai.cli report --days 365   # → data/reports/report.md
```

- 騎手: 勝率・複勝率・`win_ae`・**`mkt_ae`（市場比）とその 90% 区間**・人気度・単勝回収率・判定
- 騎手の固有の腕: 馬の強さを統制した条件付きロジットの騎手係数
- 馬: レーティング上位
- **歪みの棚卸し**: オッズ帯／人気順／前走着順／馬場水分適性／負担重量の増減／馬体重の増減／騎手の人気度／乗り替わり
  ごとの A/E 比（実勝利 ÷ 市場の期待勝利）。信頼区間が 1 をまたがなければ「過小評価」「過大評価」と表示。

### 4. 結果を HTML ダッシュボードで見る

```bash
python -m banei_ai.cli dashboard --data data/interim/races.csv \
  --preds data/reports/walkforward_preds.pkl --pred-csv data/reports/pred_20261102.csv
# → data/reports/dashboard.html (ネット接続不要の1ファイル。スマホでも見やすいレイアウト)
```

サマリー（本番投入の目安を満たすか）／確率の較正／期待値しきい値と回収率／累積損益／オッズの歪み（A/E と 90% 区間）／
騎手／馬／本日の予測／オッズ低下・ズレへの頑健性。シミュレーションデータの場合は最上部に警告が出ます（`docs/dashboard.md`）。

### 5. 本番モデルを学習して当日予測

```bash
python -m banei_ai.cli train                            # → data/models/model.pkl
python -m banei_ai.cli predict --date 2026-11-02        # 出馬表(netkeiba) + 現在オッズ(keiba.go.jp)
python -m banei_ai.cli predict --date 2026-11-02 --race 7
python -m banei_ai.cli predict --date 2026-11-02 --card card.csv   # 出馬表 CSV を自分で渡す
```

> ⚠️ **出馬表の取得元は、過去データを集めた取得元と必ず揃えてください**（`--card-source netkeiba|keibago`, 既定 netkeiba）。
> netkeiba と keiba.go.jp では馬・騎手の ID 体系が違うため、混ぜると当日の全馬が「初出走」扱いになり、
> 予測がほぼオッズそのままになります（その場合は警告を表示します）。オッズは馬番で結合するのでどちらでも構いません。

出力列:

| 列 | 意味 |
|---|---|
| 市場確率 | 単勝オッズから逆算した勝率（レース内で合計100%） |
| 能力確率 | Stage1（オッズ不使用）だけの勝率 |
| **AI勝率** | 市場と能力を合成した最終勝率 |
| AI3着内率 | Harville 式による3着以内確率 |
| **歪み** | AI勝率 ÷ 市場確率 − 1（%）。プラスなら市場が過小評価 |
| **期待値** | AI勝率 × 単勝オッズ。1.10 以上が既定の購入条件 |
| 適正オッズ | 1 ÷ AI勝率 |
| 複勝下限 / 複勝期待値 | 公式サイトから複勝オッズが取れた場合のみ。的中確率 × 複勝オッズ下限（8頭以上は3着以内、5〜7頭は2着以内で計算） |
| **プラス要因 / マイナス要因** | 能力スコアを押し上げ／押し下げている要因（SHAP 値をレース内平均と比較し「騎手の腕」「負担重量」「近走着順」などにまとめたもの） |
| 馬レート / 騎手力 / 水分適性 | 根拠の確認用 |
| 推奨 / ケリー額 | 購入条件を満たす馬に ◎、1/4ケリーでの金額（資金10万円・1点上限3%） |

毎日の運用は `scripts/daily.sh` にまとめてあります（昨日までの結果を追加取得 → 月曜は再学習 → 今日の予測）。

```bash
scripts/daily.sh            # 全レース
scripts/daily.sh --race 7   # 7R だけ (締切直前の再計算に)
```

購入条件は `backtest.BetRule`（期待値≥1.10、AI勝率≥3%、オッズ≤50倍、1レース最大2頭）。`--min-ev` で変更可能。

## シミュレーションでの動作検証

開発環境からは実データを取得できなかったため、`banei_ai/simulate.py` の**人工データ**でパイプラインを検証しました。
市場（オッズ）には意図的に次の歪みを埋め込んであります:
大穴の過剰人気／人気騎手の過大評価／前走着順への過剰反応／馬場水分適性の無視／馬体重大幅減の軽視。
（一方で市場は、モデルが見られない情報＝調教の気配なども持っている設定）

```bash
python -m banei_ai.cli simulate
python -m banei_ai.cli backtest --data data/interim/simulated.csv
python -m banei_ai.cli report   --data data/interim/simulated.csv
```

結果（2024-06〜2025-09, 1,891 レース, 完全サンプル外）:

| モデル | 対数損失 | 市場比 |
|---|---:|---:|
| 市場（オッズそのまま） | 1.9925 | 0 |
| ファンダメンタル（Stage1のみ） | 2.0914 | −0.099 |
| **合成モデル** | **1.9638** | **+0.029** |
| （参考）真の確率 | 1.8324 | +0.160 |

- 期待値 ≥ 1.10 の単勝: 767 点、的中率 29.6%、回収率 125%（90%区間 112〜138%）
- 前半で選んだしきい値 (1.3) を後半に適用: 54 点、回収率 163%（90%区間 101〜231%。点数が少なく幅が広い）
- 確率の較正: AI勝率 5〜10% の帯で実際 7.4%、20〜30% の帯で実際 24.0% など、ほぼ一致
- 市場確率だけで期待値 ≥ 1.0 を探すと**0 件**（市場だけでは歪みは見つからない＝健全性チェック）
- 歪みレポートは埋め込んだ 5 種類の歪みをすべて「過大評価／過小評価」として検出
- 推定した騎手の腕と真の腕の相関 **0.947**
- Stage2 の `j_popularity` 係数が負 → 「人気騎手の過大評価」をモデル自身が発見

#### 設計を決めるために行った比較実験（シミュレーション, 合成モデルの対数損失改善 vs 市場）

（「騎手×馬場水分」特徴量の追加前の数値。追加後に seed 42 で再実行しても lambdarank +0.0246 / rank_xendcg +0.0287 / binary +0.0224 と順位は同じ）

| Stage1 の学習方式 | seed 42 | seed 7 | seed 123 |
|---|---:|---:|---:|
| lambdarank | +0.0255 | +0.0243 | +0.0274 |
| **rank_xendcg（採用）** | **+0.0280** | **+0.0273** | **+0.0278** |
| binary（勝ち/負け） | +0.0225 | − | − |

| Stage2 に入れる市場系特徴量 | seed 42 | seed 7 |
|---|---:|---:|
| s1 + 市場確率のみ | +0.0239 | +0.0234 |
| **+ 騎手人気度・前走の市場シェア（採用）** | **+0.0280** | **+0.0273** |
| + 前走着順・馬体重増減 | +0.0294 | +0.0280 |

最後の行がわずかに良いものの、前走着順・馬体重はシミュレーションに意図的に埋め込んだ歪みそのものなので、
「答えを知っているテストへの合わせ込み」を避けて既定には入れていません。
実データで試す場合は `python scripts/experiments.py --data data/interim/races.csv` で同じ比較を再現できます
（採用するなら `banei_ai/model.py` の `STAGE2_MARKET_EXTRA` を変更）。

#### 空振りテストと頑健性（`docs/robustness.md`）

歪みを一切入れない「効率的な市場」（全馬の真の期待値 ≒ 0.80）で、**モデルが偽の優位を作らないこと**を 12 通りのデータで確認しました。
市場に対する対数損失の改善は平均 −0.003（市場より良くならない）、購入した馬の真の期待値は 0.79〜0.80 で、
未来情報の混入もありません（`tests/test_null_market.py`）。歪みの強さを変えると、検出できる優位は歪みの2乗に比例して増え、
控除率 20% を超えて利益が出るのは歪みが既定の半分〜同程度ある場合でした。

#### 何が優位を生んでいるか（`docs/model_experiments.md`）

| 取り除いた情報 | 市場に対する優位の減少 |
|---|---:|
| 能力モデル全体（オッズの歪みの補正だけ残す） | −0.019（優位の約2/3） |
| 馬の情報すべて | −0.009 |
| 騎手の情報すべて | −0.005 |
| 騎手の人気度（Stage2） | −0.005 |

オッズの歪みの補正（大穴の過剰人気・人気騎手の過大評価）だけでも市場より正確になりますが、それだけでは控除率を超えられず、
**馬と騎手の情報が加わって初めて利益が見込める**、という結果でした。
ほかに 7 つの改善案（バギング、正則化の自動調整、市場項の非線形化、早期打ち切り など）を3つのデータで試し、
一貫して良くなったものは無かったため不採用にしています（採用はシーズン中の負担重量の上昇に対応した特徴量1つのみ）。

**これらはあくまで「仕組みが正しく動くか」の確認であり、実際のばんえい競馬で同じ回収率が出ることを意味しません。**
実際の市場はこのシミュレーションよりずっと効率的なはずです。実データで `backtest` を回して判断してください。

## 実運用上の注意

- **しきい値選びの楽観バイアス**: `backtest` の表から一番良い `min_ev` を選ぶと、その期間に合わせ込んだ分だけ楽観的になります。
  期間を前後半に分け、前半で選んだしきい値が後半でも通用するか確認してください。
- **Stage1 のスコアの尺度**: 本番モデルの Stage1 と Stage2 の組み合わせによる尺度のずれは、検証で問題にならないことを確認済みです（`docs/model_experiments.md`）。
- **1点の金額**: 単勝売上 250 万円規模のレースなら 1 点 1 万円程度まではほぼ影響なし、売上 50 万円の小さいレースでは
  1 万円で回収率が明確に下がります。最適な金額の目安は「(期待値−1)÷2 × その馬に既に入っている金額」（`docs/backtest_realism.md`）。
- **締切直前の再計算**: オッズが動いたら、古い AI 勝率に新しいオッズを掛けるのではなく、`predict` を再実行して AI 勝率ごと計算し直してください
  （シミュレーションでは、前者は回収率が 125%→101% まで落ち、後者はほぼ落ちませんでした）。

- **オッズのタイミング**: 学習・検証は確定オッズ。購入時点のオッズはズレるので、締切直前に `predict` を再実行するのが望ましい。
- **プールが小さい**: ばんえいは売上が小さく、自分の購入でオッズが下がります。期待値ぎりぎりの馬は購入でマイナスに転じ得ます。
- **データ期間**: 騎手・馬の評価が安定するまで最低1年、できれば3年以上のデータを推奨。
- **再学習**: 月1回程度 `scrape` → `train` で更新。

## 今後の改善案

- 複勝・馬連など他券種（Harville 確率は実装済み、複勝オッズの取得と検証が必要）
- 調教タイム・血統（父系の重馬場適性）・障害（第2障害）通過順位の取り込み
- 締切前オッズの時系列（オッズの動き＝情報の流入）を特徴量化
- 騎手×馬場水分、騎手×クラスの交互作用

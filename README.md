# ばんえい競馬 予測AI (banei_ai)

帯広ばんえい競馬の単勝を対象に、

1. **馬の良し悪し**（レーティング・近走・水分/負担重量補正タイム・馬場水分適性・負担重量の増減）
2. **騎手の良し悪し**（経験ベイズで縮小した勝率、馬の強さを統制した固有の腕）
3. **オッズの歪み**（市場が付けた確率と実際の勝率のズレ）

の3つを組み合わせ、「**市場（オッズ）が間違えている馬**」を探すためのツール一式です。

> ⚠️ 馬券の購入は自己責任で。バックテストの回収率は将来の利益を保証しません。

---

## 考え方

### なぜ「オッズの歪み」なのか
単勝オッズは大勢の予想の集約で、それ自体がかなり正確な勝率予測です。
「強い馬を当てる」だけでは、強い馬は人気になってオッズが下がるので儲かりません。
儲かる可能性があるのは **AIの勝率 × オッズ > 1（期待値プラス）** の馬、つまり
**市場がその馬の勝率を低く見積もりすぎている（歪んでいる）** 場合だけです。

### 二段階モデル（Benter 方式）

```
                ┌──────────────────────────────┐
 過去成績 ───▶ │ 特徴量 (時点整合: 前日までの結果だけ) │
                └──────────────┬───────────────┘
                               ▼
           Stage1: LightGBM LambdaRank (オッズは使わない)
                  → 馬・騎手・負担重量・水分から「強さスコア s1」
                               ▼
           Stage2: 条件付きロジット
                  u = a·s1 + b·log(市場確率) + c·騎手人気度 + ...
                  → AI勝率 p_model (レース内で合計 1)
                               ▼
     歪み = p_model / 市場確率 − 1      期待値 = p_model × 単勝オッズ
```

- Stage1 にオッズを入れないのは、モデルが市場の真似をするだけになるのを防ぐため。
- Stage2 で「市場の情報」と「モデルの情報」を最適な重みで混ぜます。
  Stage2 の係数を見ると、市場がどこで間違えているかが分かります
  （例: `j_popularity` の係数が負 → 人気騎手は市場に過大評価されている）。
- Stage2 は Stage1 の**サンプル外**スコアだけで学習します（過信を防ぐ）。

### 特徴量（`banei_ai/features.py`）

| 区分 | 主な特徴量 | 意味 |
|---|---|---|
| 馬 | `h_rating` | 多頭数 Elo レーティング（誰に勝ったか） |
| 馬 | `h_spd_*` | **水分・負担重量補正タイム**（基準タイム − 実タイム, 秒）。基準は過去データだけで逐次推定 |
| 馬 | `h_ewm_pct`, `h_last1_pct` … | 近走の着順パーセンタイル（時間減衰平均） |
| 馬 | `h_avg3_gap`, `h_best5_gap` | 勝ち馬とのタイム差 |
| 馬 | `h_moist_apt` | 今回と同じ水分帯での成績 − 全体平均（縮小推定） |
| 馬 | `cw_rel`, `h_cw_change`, `cw_ratio` | 負担重量のレース内相対値・前走比・馬体重比 |
| 馬 | `horse_weight_diff` | 馬体重の増減 |
| 騎手 | `j_win_ae`, `j_top3_ae` | 実勝利 ÷ 期待勝利(1/頭数)。経験ベイズで縮小、時間減衰あり |
| 騎手 | `j_mkt_ae` | 実勝利 ÷ **市場の**期待勝利(Σ市場確率)。>1 なら市場が過小評価 |
| 騎手 | `j_popularity` | 騎手の人気度（平均市場シェア×頭数） |
| 調教師 | `t_win_ae` | 同上（調教師） |
| コンビ | `jh_win_ae` | 騎手×馬コンビの実績 |
| 相対 | `r_*_diff`, `r_*_rank` | 上記のレース内での平均との差・順位 |

すべて「その日より前の結果」だけから作ります（`tests/test_core.py::test_no_future_leakage` で検査）。

## 使い方

### 1. 過去データを集める

```bash
# netkeiba (結果表に単勝オッズ・人気・タイム・馬体重がまとまっている)
python -m banei_ai.cli scrape --start 2026-10-01 --end 2026-10-31 --source netkeiba --check
# 問題なければ期間を広げる (3年分 ≒ 450開催日 × 11R、2秒間隔で数時間)
python -m banei_ai.cli scrape --start 2023-04-01 --end 2026-10-31 --source netkeiba
# 公式 keiba.go.jp を使う場合
python -m banei_ai.cli scrape --start 2026-10-01 --end 2026-10-31 --source keibago --check
```

- 取得した HTML は `data/raw/` にキャッシュされ、再実行時は再取得しません。
- **各サイトの利用規約・robots.txt を確認し、私的利用の範囲で低頻度に**使ってください（既定 2 秒間隔）。
- ⚠️ 開発環境から実サイトにアクセスできなかったため、パーサーは**実ページで未検証**です。
  表の見出し語（着順・馬番・馬名・騎手・負担重量/斤量・タイム・単勝・人気・馬体重）で列を特定する方式なので
  多少のレイアウト差には耐えますが、まず `--check` で1か月分の中身（特に `moisture`=馬場水分、
  `odds_win`、`horse_id`）が埋まっているか確認してください。
  ずれていたら `banei_ai/scrape/common.py` の `HEADER_RULES` / `find_moisture` を調整します。

手持ちの CSV がある場合（日本語見出し可）:

```bash
python -m banei_ai.cli import-csv --in mydata.csv
```

必要な列（`banei_ai/schema.py` 参照）: `date, race_no, post(馬番), horse_name(馬名), jockey_name(騎手), finish(着順)`
＋ あると良い列: `odds_win(単勝), carried_weight(負担重量), moisture(馬場水分), time(タイム), horse_weight(馬体重), race_class`。

### 2. 検証する（ウォークフォワード・完全サンプル外）

```bash
python -m banei_ai.cli backtest            # → data/reports/backtest.md
```

2か月ごとに「それ以前のデータだけで学習 → 次の2か月を予測」を繰り返し、
- 対数損失（市場そのまま／較正後／ファンダメンタル／合成モデル）
- 期待値しきい値ごとの回収率・的中率・最大ドローダウン・1/4ケリーの資金推移
- 回収率の 90% 信頼区間（レース単位ブートストラップ）、四半期ごとの安定性、確率の較正

を出します。**合成モデルの `vs_market` がプラス**で、**回収率の信頼区間の下限が 1 を超える**かが本番投入の目安です。

### 3. 騎手・馬・歪みのレポート

```bash
python -m banei_ai.cli report --days 365   # → data/reports/report.md
```

- 騎手: 勝率・複勝率・`win_ae`・**`mkt_ae`（市場比）とその 90% 区間**・人気度・単勝回収率・判定
- 騎手の固有の腕: 馬の強さを統制した条件付きロジットの騎手係数
- 馬: レーティング上位
- **歪みの棚卸し**: オッズ帯／人気順／前走着順／馬場水分適性／負担重量の増減／馬体重の増減／騎手の人気度／乗り替わり
  ごとの A/E 比（実勝利 ÷ 市場の期待勝利）。信頼区間が 1 をまたがなければ「過小評価」「過大評価」と表示。

### 4. 本番モデルを学習して当日予測

```bash
python -m banei_ai.cli train                            # → data/models/model.pkl
python -m banei_ai.cli predict --date 2026-11-02        # keiba.go.jp から出馬表と現在オッズを取得
python -m banei_ai.cli predict --date 2026-11-02 --race 7
python -m banei_ai.cli predict --date 2026-11-02 --card card.csv   # 出馬表 CSV を自分で渡す
```

出力列:

| 列 | 意味 |
|---|---|
| 市場確率 | 単勝オッズから逆算した勝率（レース内で合計100%） |
| 能力確率 | Stage1（オッズ不使用）だけの勝率 |
| **AI勝率** | 市場と能力を合成した最終勝率 |
| AI複勝率 | Harville 式による3着以内確率 |
| **歪み** | AI勝率 ÷ 市場確率 − 1（%）。プラスなら市場が過小評価 |
| **期待値** | AI勝率 × 単勝オッズ。1.10 以上が既定の購入条件 |
| 適正オッズ | 1 ÷ AI勝率 |
| 馬レート / 騎手力 / 水分適性 | 根拠の確認用 |
| 推奨 / ケリー額 | 購入条件を満たす馬に ◎、1/4ケリーでの金額（資金10万円・1点上限3%） |

購入条件は `backtest.BetRule`（期待値≥1.10、AI勝率≥3%、オッズ≤50倍、1レース最大2頭）。`--min-ev` で変更可能。

## シミュレーションでの動作検証

開発環境からは実データを取得できなかったため、`banei_ai/simulate.py` の**人工データ**でパイプラインを検証しました。
市場（オッズ）には意図的に次の歪みを埋め込んであります:
大穴の過剰人気／人気騎手の過大評価／前走着順への過剰反応／馬場水分適性の無視／馬体重大幅減の軽視。
（一方で市場は、モデルが見られない情報＝調教の気配なども持っている設定）

```bash
python -m banei_ai.cli simulate
python -m banei_ai.cli backtest --data data/interim/simulated.csv
python -m banei_ai.cli report   --data data/interim/simulated.csv
```

結果（2024-06〜2025-09, 1,891 レース, 完全サンプル外）:

| モデル | 対数損失 | 市場比 |
|---|---:|---:|
| 市場（オッズそのまま） | 1.9925 | 0 |
| ファンダメンタル（Stage1のみ） | 2.1066 | −0.114 |
| **合成モデル** | **1.9670** | **+0.026** |
| （参考）真の確率 | 1.8324 | +0.160 |

- 期待値 ≥ 1.10 の単勝: 591 点、的中率 29.8%、回収率 120%（90%区間 107〜134%）
- 市場確率だけで期待値 ≥ 1.0 を探すと**0 件**（市場だけでは歪みは見つからない＝健全性チェック）
- 歪みレポートは埋め込んだ 5 種類の歪みをすべて「過大評価／過小評価」として検出
- 推定した騎手の腕と真の腕の相関 **0.947**
- Stage2 の `j_popularity` 係数が負 → 「人気騎手の過大評価」をモデル自身が発見

**これらはあくまで「仕組みが正しく動くか」の確認であり、実際のばんえい競馬で同じ回収率が出ることを意味しません。**
実際の市場はこのシミュレーションよりずっと効率的なはずです。実データで `backtest` を回して判断してください。

## 実運用上の注意

- **オッズのタイミング**: 学習・検証は確定オッズ。購入時点のオッズはズレるので、締切直前に `predict` を再実行するのが望ましい。
- **プールが小さい**: ばんえいは売上が小さく、自分の購入でオッズが下がります。期待値ぎりぎりの馬は購入でマイナスに転じ得ます。
- **データ期間**: 騎手・馬の評価が安定するまで最低1年、できれば3年以上のデータを推奨。
- **再学習**: 月1回程度 `scrape` → `train` で更新。

## 今後の改善案

- 複勝・馬連など他券種（Harville 確率は実装済み、複勝オッズの取得と検証が必要）
- 調教タイム・血統（父系の重馬場適性）・障害（第2障害）通過順位の取り込み
- 締切前オッズの時系列（オッズの動き＝情報の流入）を特徴量化
- 騎手×馬場水分、騎手×クラスの交互作用

## ファイル構成

```
banei_ai/
  schema.py      正規データ形式 (1行 = 1レース×1頭)
  features.py    時点整合な特徴量 (馬・騎手・調教師・コンビ・スピード指数)
  market.py      オッズ→市場確率、A/E 比による歪み分析、favorite-longshot 指数
  clogit.py      条件付きロジット、Harville 3着内確率
  model.py       Stage1 (LightGBM) / Stage2 (条件付きロジット) / ウォークフォワード
  backtest.py    購入ルール、均等買い・分数ケリー、ブートストラップ、較正
  report.py      騎手・馬の評価表、歪みの棚卸し
  predict.py     当日予測
  scrape/        netkeiba・keiba.go.jp パーサー (見出し語ベース)
  simulate.py    検証用シミュレーター
  cli.py         コマンドライン
tests/           リーク検査・推定の正しさ・パーサーのテスト
```

# モデルの比較実験: 何が効いているか (アブレーション) と改善候補

> ⚠️ **ここの数値はすべてシミュレーション (`banei_ai/simulate.py` の人工データ) 上のものです。**
> 実際のばんえい競馬の成績ではありません。シミュレーションの市場には、意図的に 5 種類の歪み
> (大穴の過剰人気／人気騎手の過大評価／前走着順への過剰反応／馬場水分適性の無視／馬体重大幅減の軽視)
> が埋め込まれているので、**それに直接対応する特徴量の効き目は「シミュレーションの作り」をなぞっているだけ**です。
> 実データが集まったら、同じスクリプトを `--data` 付きで回して結論を確かめ直してください (末尾「再現方法」)。

## 要約

- **何が市場に勝つ力になっているか** (合成モデルの対数損失の市場超過 +0.0285 の内訳)
  - Stage1 (オッズを使わない能力スコア) を丸ごと外すと +0.0096 まで落ちる → 市場超過の約 2/3 は **馬・騎手の情報**、
    残り約 1/3 は **市場そのものの癖の補正** (本命-大穴バイアスの較正と「人気騎手」補正)。
  - **馬の情報**をまとめて外すと −0.0089、**騎手の情報**をまとめて外すと −0.0048。
    ただし馬の分のほとんどは、埋め込んだ歪みに対応する「馬場水分適性」(−0.0056) と「馬体重」(−0.0021)。
  - 勝ち馬を当てる力そのもの (Stage1 だけの対数損失) では逆に**騎手の情報の方が大きい** (+0.079 悪化 vs 馬 +0.024)。
    騎手の腕は市場もある程度織り込んでいるので、「当てる力」ほどには「市場に勝つ力」にならない。
  - **オッズの歪み**では、Stage2 の「騎手の人気度」(人気騎手は買われすぎ) が −0.0049 と効く。前走の市場シェアはほぼ 0。
- **採用した変更**: 1 つだけ。**季節に頑健な重量の前走比 `h_cw_rel_change`** (今回と前走の「レース平均との重量差」の差) を
  Stage1 に追加。シミュレーションでは 3 シードとも悪化せず平均 +0.0003 (ノイズ程度)。実際のばんえいは基礎重量が
  開催回ごとに 10kg ずつ上がる (年度初めに戻る) ため、生の重量差 `h_cw_change` には季節の要因が混ざる、という現実の
  ルール (docs/research_banei.md) が採用理由。
- **見送った変更**: (a) Stage1 のアンサンブル・バギング、(b) Stage2 の正則化の自動選択、(c) 市場項の 2 乗、
  (d) 学習回数の自動選択、(e) 本番モデルの尺度ずれ対策 (レース内標準化・最後の OOS モデル・新しさの重み付け)。
  **どれも 3 シードすべてで改善するものは無く**、多くは 3 シードとも悪化した。仕組み (コード) は残してあるので、
  実データでは `scripts/ablation.py --part candidates --data ...` で再評価できる。
- **本番モデルの尺度ずれ**: 本番の手順 (`BaneiModel.fit`) とウォークフォワード検証は、ブロック境界で切れば**完全に同じ予測**
  になることを確認した。つまり README の「尺度のずれ」はバックテストの成績にすでに織り込まれている。
- **歪みのない市場での確認** (L4 の `efficient` プリセット): 採用後のモデルも市場に勝てず (Δ = −0.0010〜−0.0036)、
  選ばれた賭けの真の期待値は 0.80 (<1)。存在しないエッジをでっち上げていない。L4 の帰無検定 `tests/test_null_market.py` も全件通過。

## 1. 実験の設定

| 項目 | 内容 |
|---|---|
| データ | `simulate(SimConfig(end="2025-09-30", seed=s))`、s = 42 / 7 / 123。各 約 3,530 レース (2023-04〜2025-09) |
| 評価 | `walk_forward` と同じ完全サンプル外の予測 (2 ヶ月ブロック)。評価期間は 2024-06〜2025-09 の **約 1,880 レース/シード** |
| 合成 vs市場 | 合成モデル `p_model` の 1 レースあたり対数損失の、市場 (オッズそのまま) に対する改善。正が良い |
| 能力LL | Stage1 だけ (オッズ不使用) の勝率 `p_fund` の対数損失。小さいほど良い |
| 寄与 / 改善 | 変更前後の合成モデルの対数損失の差 (レース単位で対応をとった平均)。±SE はレース単位の標準誤差 (3 シード平均では平均の SE) |
| 点数・回収率 | 点数は 1 シードあたり。既定の購入ルール `backtest.BetRule()` (期待値 ≥ 1.10・勝率 ≥ 3%・オッズ ≤ 50 倍・1 レース 2 頭まで) の単勝均等買い。回収率は 3 シードの点数で重み付けした合算 |
| 真のEV | 買った馬券の「真の勝率 × オッズ」の平均 (運に左右されない「本当の」期待値)。実データには無い。2〜3 章は `_p_true` (第2障害での停止の偶然を含まない近似)、4 章は L4 の `true_win_probs` (停止込みの厳密値) を使用 |

**ノイズの目安**: 同じ設定で LightGBM の乱数シードだけ変えると、合成モデルの対数損失は 1 シードあたり ±0.001 程度動く
(3 シード平均で +0.0011±0.0005)。列の順番を変えただけでも (LightGBM の `feature_fraction` が列順に依存するため) 同じくらい動く。
**±0.001 未満の差は「誤差の範囲」**と読んでください。

### 読み方

**馬の良し悪し**
- 馬の情報をまとめて外すと市場超過の 1/3 (−0.0089) が消える。ただし内訳の大半は「馬場水分適性」と「馬体重」で、
  これはシミュレーションの市場が**意図的に無視している**情報。実際の市場がこれらをどれだけ織り込んでいるかは不明。
- 実績・近走・スピード指数は**単独で外してもほぼ影響が無い**。レーティング・着順・着差・スピード指数は互いに
  同じ「馬の強さ」を別の角度から測っているので、1 つ欠けても他で補える (冗長)。まとめて外すと効く。
- 負担重量 (+0.0046、能力LL では +0.074 と最大級) が効くのは、ばんえいのハンデ (実績上位ほど重い) が
  「その馬の強さについての公開情報」になっているため。シミュレーションでも重量は実績順位で決まる。

**騎手の良し悪し**
- 勝ち馬を当てる力 (能力LL) では騎手の情報が最も大きい (+0.079)。良い騎手ほど強い馬に乗る傾向と、騎手自身の腕の両方を拾っている。
- しかし**市場に勝つ力**としては馬の情報の約半分 (+0.0048)。騎手の腕は市場もかなり織り込んでいるため。
  残っている分は主に「人気騎手が買われすぎ」(シミュレーションに埋め込んだ歪み) を見抜く分で、Stage2 の `j_popularity` (−0.0049) と対になる。
- 騎手×馬場水分 (+0.0008) とコンビ・乗り替わり (+0.0002) は誤差程度。シミュレーションにはこれらの効果が無いので当然で、
  実データでは別途確認が要る (無害なので残している)。

**市場 (オッズの歪み)**
- Stage1 を丸ごと外した「市場の情報だけ」のモデルでも +0.0096。これは本命-大穴バイアスの較正 (`log_p_mkt` の係数 < 1) と
  人気騎手の補正による。ただし購入点数は 17 点・真のEV 0.99 で、**市場の情報だけでは控除 20% を越えられない**。
  控除を越える賭けを見つけるには、Stage1 の「馬・騎手の情報」と組み合わせることが必要。
- 前走の市場シェアは 3 シードとも外した方がわずかに良い (+0.0005±0.0004) が、有意ではなく、実データでは効く可能性もあるので残している。

### (a) Stage1 のアンサンブル・バギング — 見送り
- 乱数シード違いの 3 本平均は能力LL をわずかに改善 (2.0808 → 2.0786) するが、合成モデルでは ±0 (+0.0005 / −0.0004 と割れる)。
  乱数シードによる ±0.001 のばらつきは「偏り」ではなく「ばらつき」なので、平均しても期待値は変わらない、と読める。
- lambdarank を混ぜると 3 シードとも悪化。rank_xendcg 単独の方が良いという既存の比較 (README) と整合的。

### (b) Stage2 の正則化 — 見送り
- Stage2 の説明変数は 4 つ、学習レースは数百〜千数百あるので、正則化はほとんど要らない。
  内側の時系列分割 (学習期間の最後 25%) で選ぶと、検証期間が短く選択がぶれる分だけ 3 シードとも悪化した。
- 補足: 現在の L2 は全係数を 0 (= 一様な確率) に向けて縮める形。縮める先を「市場そのまま」にする方が理屈には合うが、
  正則化自体がほぼ不要なので試していない。

### (c) 市場項の 2 乗 (非線形な本命-大穴バイアス) — 見送り
- 実際の競馬では、本命-大穴バイアスは大穴側で特に強い非線形なもの、という報告が多い。そのため `Stage2(market_sq=True)` で
  (log 市場確率)² を足せるようにした。
- シミュレーションの市場は q ∝ p^0.85 (べき乗) で歪めてあり、これは log 確率に対して**線形**なので、2 乗の項は効きようがない。
  実際に 3 シードとも −0.0002〜−0.0006 とわずかに悪化。**実データでは試す価値がある** (コードは残してある)。

### (d) 学習回数の自動選択 — 見送り
- 学習期間の最後 20% を検証に取り、検証期間での条件付きロジットの対数損失 (s1 + log 市場確率) で回数を選ぶ実装。
- 選ばれた回数が 62〜1,503 回 (seed 42 の各ブロック) と大きくぶれ、3 シードとも悪化。検証期間の損失曲線が平らで、
  数か月分の検証データでは最適な回数を見分けられない。固定の 400 回は 200 回・800 回のどちらより良いか同等。

### (e) 本番モデルの「Stage1 スコアの尺度ずれ」 — 対策不要と判断
README の注意書き「本番モデルは全期間で学習した Stage1 に、より短い期間の Stage1 で較正した Stage2 を組み合わせている」を検証した。

**実験**: 打ち切り日 cut を 2025-02 / 04 / 06 / 08 の 1 日に置き、cut より前のデータだけで `BaneiModel.fit` と同じ手順で学習 →
cut から 2 ヶ月を予測 (各シード約 940 レース)。

|---|---:|---:|---:|---:|
| 現行 (全データの Stage1 + OOS s1 で学習した Stage2) | 0 | 0 | 0 | 0 |
| Stage1 を「Stage2 の学習に使った最後のブロックのモデル」にする | −0.0015 ±0.0009 | −0.0013 | −0.0018 | −0.0013 |

尺度の診断 (12 回 = 3 シード × 4 打ち切り日):
- s1 のレース内標準偏差の比 (全データの Stage1 ÷ 最後の OOS モデル、予測期間で測定) は 0.986〜1.058。12 回中 11 回は ±1.7% 以内。
- Stage2 の学習に使った OOS スコアの標準偏差 (0.387〜0.413) と、本番の Stage1 のスコアの標準偏差 (0.387〜0.418) も同じ水準。
- 後知恵で最適な s1 の倍率 (予測期間の結果を見てから選んだ倍率。1 なら尺度ずれ無し) は 0.65〜1.80、平均 1.14。
  2 ヶ月 (約 235 レース) では推定が大きくぶれ、シードによって 1 より上だったり下だったりする。

**結論**
- **本番の手順とウォークフォワード検証は、ブロック境界で切れば完全に同じ予測になる** (上表の最終行)。
  ウォークフォワードでも「ブロック k を予測する Stage1 は k の直前までの全データで学習し、Stage2 はそれより前のブロックの
  OOS スコアで学習する」ので、本番と同じ構造の尺度ずれをすでに含んでいる。つまり **バックテストの成績は、このずれを含んだ数字**。
- s1 のレース内標準偏差は学習データ量が変わってもほぼ一定。後知恵で最適な s1 の倍率は平均 1.14 とやや 1 を上回るが、ぶれが大きく (0.65〜1.80)、s1 の重みを実質的に大きくする (e') も効かなかった。
- 「最後の OOS モデルを本番に使う」は尺度は揃うが 2 ヶ月古いデータで学習した Stage1 になり、3 シードとも悪化した (−0.0013〜−0.0018)。
  「レース内標準化」は本命が抜けたレースとそうでないレースの区別を消してしまい、悪化することが多い。
- 別の見方として「後のブロックほど Stage1 の学習データが多く s1 の情報量が増えるので、古いブロックで決めた s1 の重みは
  小さすぎるのでは」という仮説も (e') で試したが、新しいレースを重くするほど悪化した (半減期 90 日で −0.0014〜−0.0021、旧ベースラインで確認)。
  Stage2 は等しい重みで多くのレースを使う方が良い。

### (f) 季節に頑健な重量の前走比 — 採用
- 実際のばんえいでは、クラスごとの基礎重量が開催回ごとに約 10kg ずつ上がり、年度初めに戻る
  (例: A1 は開幕時 650kg → 年度末 730kg。docs/research_banei.md Q5)。牝馬 −20kg、☆騎手 −10kg もある。
  そのため既存の `h_cw_change` (今回の重量 − 前走の重量) は「ハンデキャッパーの見直し」と「季節の上昇」が混ざる。
- `h_cw_rel_change` = (今回の重量 − 今回のレース平均) − (前走の重量 − 前走のレース平均)。レース内の相対値どうしの差なので
  季節の上下が打ち消され、「周りと比べて重くされたか軽くされたか」だけが残る。
- 現在のシミュレーターには季節の上昇が無いので、ここでは「悪化しないこと」を主に見た: 3 シードとも改善 (+0.00002 / +0.0007 / +0.0002)、
  平均 +0.0003 (誤差の範囲)。歪みのない市場でもエッジを作らない (下記)。`h_cw_change` を外して置き換える (f') は 3 シードとも悪化したので、両方残す。
- 列順の違いで結果が動くのを避けるため、評価したときと同じく `FUNDAMENTAL_FEATURES` の**末尾**に追加した。

## 4. 歪みのない市場での確認 (帰無仮説)

L4 のシミュレーター (プリセット付き、commit 11f14e6) の `SimConfig.preset("efficient", end="2025-09-30", seed=s)` を使用。
市場は真の強さを完全に知り (第2障害での停止の偶然まで含めて厳密に値付け)、埋め込んだ歪みも無いので、
モデルが市場に足せる情報は原理的にゼロ。ここで「市場に勝つ」結果が出たらパイプラインの欠陥。
真のEV は L4 の `true_win_probs` (停止込みの真の勝率) × オッズ。

| モデル | 合成 vs市場 (seed 42 / 7 / 123) | 点数 (合計) | 実現回収率 (合算) | 真のEV (合算) |
|---|---|---:|---:|---:|
| 採用後 (`h_cw_rel_change` あり) | −0.0010 / −0.0030 / −0.0036 | 60 | 2.02 | 0.80 |
| 変更前 | −0.0007 / −0.0029 / −0.0036 | 48 | 2.01 | 0.80 |

- 両モデルとも市場に勝てず、選ばれた賭けの**真の期待値は 0.80 (控除 20% 相当) で 1 を大きく下回る**。
  モデル自身は期待値 1.1 以上と見積もって選んでいるので、これは選択バイアス (勝者の呪い) の大きさでもある。
- 実現回収率が 2 倍になっているのは**少ない点数での運**。真の期待値 0.80 の賭けを 60 点買えば、この程度の振れは普通に起きる
  (L4 の 12 シードの検証でも seed 42 などで同様)。点数の少ない回収率は信用しないこと。
- L4 の `tests/test_null_market.py` (commit 11f14e6: efficient での帰無検定 Δ < 0.006・区間下限 < 1・真の期待値 < 1、
  既定市場での検出力 Δ > 0.015 など 7 件) を採用後の `model.py` / `features.py` / `clogit.py` で実行し、**全件通過**。

## 6. 注意 (シミュレーションの限界)

- 寄与の大きさはシミュレーションの設計で決まる。特に「馬場水分適性」「馬体重」「騎手の人気度」は**市場がわざと間違えるように作った**項目なので、
  実データでの寄与はずっと小さい (あるいはゼロ) かもしれない。
- 逆に、シミュレーションに入っていない効果 (騎手×馬場水分、コンビ相性、季節の重量上昇、血統、障害の巧拙など) は、ここでは評価できない。
- 差が ±0.001 未満の比較は LightGBM の乱数や列順で入れ替わる。3 シードで同じ向きでも、ほとんどの「改善」は誤差の範囲であることに注意。
- 回収率はシード・点数で大きく揺れる (例: seed 123 の購入点数は他の 1/4)。判断は対数損失と、シミュレーションなら真の期待値で行う。

## 7. 再現方法

```bash
# 3 シードの特徴量と OOS スコアを /tmp/banei_cache にキャッシュしながら実行 (1 シードあたり 約 6〜10 分, 1 スレッド)
OMP_NUM_THREADS=1 python scripts/ablation.py --part ablation   --cache /tmp/banei_cache --out ablation.md
OMP_NUM_THREADS=1 python scripts/ablation.py --part candidates --cache /tmp/banei_cache --out candidates.md
OMP_NUM_THREADS=1 python scripts/ablation.py --part scale      --cache /tmp/banei_cache --out scale.md
# シードごとに並列に回してから、全シードをまとめて再実行すると (キャッシュ済みなので速い) 3 シード平均の表が出る
OMP_NUM_THREADS=1 python scripts/ablation.py --part ablation --seeds 42 --cache /tmp/banei_cache &
# 実データで
OMP_NUM_THREADS=1 python scripts/ablation.py --part ablation --data data/interim/races.csv --cache /tmp/banei_cache_real
# 歪みのない市場 (simulate.py に SimConfig.preset があるとき)
OMP_NUM_THREADS=1 python scripts/ablation.py --part candidates --sim-preset efficient --cache /tmp/banei_cache
```

実データで候補を評価するときも、**3 期間以上 (例: 年度ごと) に分けて全期間で同じ向きに効くか**を見てから採用してください。

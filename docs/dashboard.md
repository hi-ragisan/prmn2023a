# HTML ダッシュボード

バックテスト・騎手/馬の評価・オッズの歪み・当日の推奨買い目を **1 枚の HTML** にまとめて、
ひと目で（スマホでも）確認するための機能です。

- 1 ファイルで完結します。グラフは Python で作ったインライン SVG で、CDN や外部ライブラリは使いません。
  **開くときにネット接続は不要**なので、メールやクラウドドライブ・AirDrop でスマホに送ってそのまま開けます。
- 端末の設定に合わせてライト/ダーク表示が切り替わります。
- スマホ幅（320px〜）でもページが横にはみ出しません。列の多い表だけは、表の枠の中で横にスクロールします（左端の列は固定）。
- グラフの点・棒にマウスを乗せる／タップすると数値が出ます。どのグラフにも「表で見る」があり、同じ数値を表で確認できます。

## 作り方

```bash
# 1. ウォークフォワード検証 (予測が data/reports/walkforward_preds.pkl に保存される)
python -m banei_ai.cli backtest

# 2. (任意) 当日予測 → data/reports/pred_YYYYMMDD.csv
python -m banei_ai.cli predict --date 2026-11-02

# 3. ダッシュボード
python -m banei_ai.dashboard \
    --data data/interim/races.csv \
    --preds data/reports/walkforward_preds.pkl \
    --pred-csv data/reports/pred_20261102.csv \
    --out data/reports/dashboard.html
```

| オプション | 既定 | 意味 |
|---|---|---|
| `--data` | `data/interim/races.csv` | 過去成績 CSV（騎手・馬・歪みの集計に使う） |
| `--preds` | なし | `backtest` が保存したウォークフォワード予測 (pickle)。**省略するとその場で計算**（実データ 3 年分で数分） |
| `--pred-csv` | なし | `predict` が出力した当日予測 CSV。指定すると「本日の予測」節が出る。ファイル名の日付を見出しに使う |
| `--out` | `data/reports/dashboard.html` | 出力先 |
| `--min-ev` | 1.10 | 「採用ルール」の期待値しきい値（サマリー・累積損益・しきい値グラフの強調） |
| `--days` | 365 | 騎手表の集計期間（日） |
| `--min-rides` | 50 | 騎手表に載せる最低騎乗数 |
| `--no-walkforward` | | `--preds` が無いときに計算しない（予測系の節は省略して、騎手・馬・歪みだけ出す） |

Python から使う場合は `banei_ai.dashboard.build_dashboard(df, P, pred)` が HTML 文字列を返します。

シミュレーションで試すとき:

```bash
python -m banei_ai.cli simulate --out /tmp/sim.csv
python -m banei_ai.dashboard --data /tmp/sim.csv --out /tmp/dashboard.html   # ウォークフォワードも計算 (1 分前後)
```

シミュレーションデータ（`_p_true` 列がある）から作ると、ページ上部に
**「シミュレーションデータ（実際の成績ではありません）」** という黄色い帯が出ます。
この帯が出ているページの回収率は、実際のばんえい競馬の収益性について何も意味しません。

## 見方

上から順に、目次のボタンで各節に移動できます。

### サマリー
- **本番投入の目安**: 「合成モデルの対数損失が市場より良い」かつ「前後半検証で後半の回収率の 90% 区間の下限が 100% を超える」
  の両方を満たすと ✓、どちらかが足りないと ! と理由を表示します（README の基準と同じ）。
- **評価レース数**: 完全サンプル外（学習に使っていない期間）で評価したレース数と期間。
- **対数損失の改善 (市場比)**: プラスなら、AI の勝率の方がオッズより当たっている。「対数損失の内訳」で市場（較正後）・能力のみ・合成モデルを比較できます。
- **期待値 ≥ 1.1 の回収率**: 採用ルールで 100 円ずつ買った場合の回収率と、レース単位ブートストラップの 90% 区間。
  区間が 100% をまたいでいる間は「プラスとは言い切れない」状態です。
- **前後半検証**: 前半の期間で一番良かったしきい値を選び、それを後半にそのまま当てはめた成績。しきい値選びの楽観バイアスを除いた、最も正直な目安です。

### 確率の較正
横軸が AI の予測勝率（帯ごとの平均）、縦軸が実際の勝率。**点が対角線に乗っていれば**「20% と言った馬は実際に 20% 勝つ」＝確率をそのまま信じてよい。
オレンジ（市場確率）は比較用で、本命側で線より上・大穴側で線より下に出ていれば、
市場に「本命の過小評価・大穴の過大評価」（favorite-longshot bias）があるということです（α が 1 より大きいほど強い）。

### 期待値しきい値と回収率
しきい値（AI勝率 × オッズ ≥ いくつで買うか）ごとの回収率（90% 区間つき）と購入点数。
しきい値を上げると回収率は上がりがちですが、点数が減って区間が広がります。
**表の中で一番良いしきい値を選ぶと楽観的になる**ので、選ぶ根拠はサマリーの前後半検証を優先してください。
回収率と点数は尺度が違うので、別々のグラフにしています（2 軸グラフは誤読のもとなので使いません）。

### 累積損益
採用ルールで毎回 100 円ずつ買った場合の損益の推移（確定オッズ）。縦線より右が前後半検証の「後半」。
グラフ上を横になぞると日付ごとの累積損益・点数・回収率が出ます。「月別の表で見る」で月ごとの成績も確認できます。
ずっと右肩上がりでも、確定オッズでの計算なので実際より楽観的です（下の注意を参照）。

### オッズの歪み
**A/E = 実際の勝利数 ÷ 市場（オッズ）が予想した勝利数**を、切り口ごとに点（A/E）と横線（90% 区間）で示します。1.0 が「市場どおり」。

- 青: 区間が 1 より上 → **過小評価**（市場が見落としている＝買い材料）
- 赤: 区間が 1 より下 → **過大評価**（人気しすぎ＝消し材料）
- 灰: 区間が 1 をまたぐ → 差があるとは言えない

切り口: オッズ帯 / 人気順 / 前走着順 / 馬場水分適性（その馬の今回の水分帯での得意・不得意を 5 等分）/ 負担重量の増減 / 馬体重の増減 / 騎手の人気度 / 乗り替わり。
全期間・全出走馬の集計で、切り口ごとに独立した集計です（複数の歪みの重なりはモデル側で扱います）。

### 騎手
直近 `--days` 日、`--min-rides` 騎乗以上の騎手。市場比 A/E の高い順。

| 列 | 意味 |
|---|---|
| 市場比 A/E・区間図・判定 | 実勝利 ÷ オッズが示す期待勝利。区間図の縦線が 1.0。区間が 1 より上なら「市場が過小評価 (狙い)」として行に色が付く |
| 勝率 | そのまま |
| 固有の腕 | 馬の強さ（レーティング・近走・負担重量など）を統制した条件付きロジットの騎手係数を「平均的な騎手と比べて勝ちやすさが何 % 違うか」に直したもの（騎乗数が少ないほど 0 に縮む） |
| 人気度 | 平均の市場シェア × 頭数。1 より大きいと人気を集めやすい騎手（＝過大評価されやすい） |
| 頭数比 A/E | 実勝利 ÷ 頭数から見た期待勝利（腕＋騎乗馬の質） |

オッズが無いデータでは市場との比較の列を省き、頭数比 A/E 順に並べます。

### 馬
直近 120 日以内に出走した馬のレーティング上位 20 頭（最後に出走した時点の値）。
近走指数は着順の時間減衰平均（100 = 毎回 1 着、0 = 毎回最下位）、市場比 A/E > 1 はオッズ以上に勝っている馬、
水分適性 + は前走時点の水分帯が得意だった馬です。

### 本日の予測（`--pred-csv` を指定したとき）
- **推奨買い目**: ◎ の付いた馬をカードで一覧（単勝オッズ・AI 勝率と市場確率・期待値・1/4 ケリー額・プラス要因／マイナス要因）。
- レースごとの表: 推奨のあるレースは開いた状態で、◎ の行は色付き＋左に青い線。歪み = AI勝率 ÷ 市場確率 − 1、期待値 = AI勝率 × 単勝オッズ。
- オッズは締切直前に `predict` を再実行して作り直すのが望ましい（古い AI 勝率に新しいオッズを掛けるだけだと、ズレた馬ばかり選ぶ逆選択が起きます）。

### オッズ低下・ズレへの頑健性（`backtest.robustness_table` があるとき）
自分の購入でオッズが下がる影響（プールが小さく、1 点の金額が大きいほど大きい）と、締切前に見たオッズと確定オッズのズレを入れて
計算し直した回収率です。代表的なプール額での「ズレ × 1 点の金額」ごとの回収率グラフ、
`backtest.breakeven_table` があれば「1 点あたりいくらまで買えるか（損益分岐の賭け金）」の表も出ます。
この関数を含まないバージョンでは、節ごと表示されません。

## 材料が欠けているとき

ダッシュボードは、作れない節だけ「ⓘ 省略: 理由」と表示して、残りは普通に出力します。

| 状況 | 表示 |
|---|---|
| オッズが無い | 回収率・歪み・市場比の列を省略（騎手・馬は表示） |
| ウォークフォワードできない（期間が短い等） | サマリー〜累積損益を省略し、サマリーに理由を表示 |
| 購入対象が 0 点 | KPI は「—」、累積損益は省略 |
| 予測 CSV なし | 「本日の予測」に指定方法を表示 |

## 注意

- 回収率はすべて**確定オッズ**での計算です。購入時点のオッズとのズレ、自分の購入によるオッズの低下で、実際の回収率は下がります。
- 90% 区間は「同じ実力でも運でこのくらいはぶれる」幅です。点数が少ないと区間が広くなります。
- 馬券の購入は自己責任で。
